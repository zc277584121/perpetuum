# 初始化项目

## 前置检查

确认以下能力可用：

- 当前 Agent 能加载 `perpetuum` 与必须依赖的 `cc-use` Skill；缺少 `cc-use` 时停止初始化，不建立 Harness；
- `tmux` 可用；
- 对应的交互式 Codex 或 Claude Code TUI 可启动；
- Python 3.8 或更高版本可用；
- MemSearch 是可选依赖；若已安装则确认可正常检索，不可用时直接跳过。

不要在初始化过程中更新 Agent、Skill、插件或认证。版本不兼容时记录问题并让用户决定。

## 初始化步骤

1. 解析用户指定或当前所在的项目目录，取得绝对路径。
2. 默认继承当前调用 Perpetuum 的 Agent 类型。只有用户明确要求时才覆盖为其他 Agent。
3. 若 MemSearch 可用，检索这个项目的历史目标、近期进展、用户偏好、可用资源、边界、已做决定和可能的下一步。
4. 检查项目中的说明文档、配置、最近状态和可验证证据。不要把 MemSearch 记忆直接当成事实。
5. 在对话中起草初始化契约，不要提前调用注册命令或在运行时目录创建半成品 Harness。
6. 检查信息是否足以支持长期自主运行。至少确认项目目录与名称、长期目标、当前背景与进度、可用资源与权限、边界与底线、进展证据、工作时间窗口，以及长期目标之外必须兼顾的要求。Agent 类型默认继承当前 Agent，除非用户明确覆盖。
7. 对无法可靠推断、互相矛盾或会改变行为的内容逐项询问。用户回答后重新整理完整摘要；若仍有缺口，继续询问和确认，不要因为已经进行过一轮问答就跳过剩余问题。
8. 向用户展示最终的 `goal.md`、初始 `plan.md`、`history.md` 摘要及运行配置。只有在用户明确确认这些内容无误后，才调用单一入口注册项目：

```bash
<skill-directory>/scripts/perpetuum project add <project-path> \
  --name "<project-name>" \
  --agent <codex-or-claude> \
  --window "<HH:MM-HH:MM>"
```

9. 用确认后的内容替换自动生成的 `goal.md`、`plan.md`、`history.md`，再检查其他通信文件的标题和项目背景。
10. 启动服务并展示前端地址。若配置地址已经运行同一运行时目录的 Perpetuum 前端，直接复用，不重启，也不另选端口：

```bash
<skill-directory>/scripts/perpetuum start
```

若端口被其他服务或不同运行时目录的 Perpetuum 占用，停止并向用户说明冲突；不要擅自结束该服务、重启它或自动换端口。

注册结果只在 `project.yaml` 中记录 Agent 类型。不要把 shell alias、可执行文件绝对路径、权限参数或 cc-use 运行参数写入项目配置；这些由 Runner 和 cc-use 各自统一管理。

## 注册确认门槛

“用户说了一个长期方向”不等于已经授权建立 Harness。初始化 Agent 必须让用户能够看清最终会长期执行什么、使用哪些资源、在什么时间运行、哪些边界不能越过，以及用什么证据判断进展。可以从 MemSearch 和项目文件中推断并减少提问，但所有关键推断仍要放进最终摘要让用户确认。

用户尚未确认时，把草稿保留在当前对话中，不写入 `~/.perpetuum/projects/`。用户修改任一关键内容后，重新给出合并后的完整摘要并再次确认。

## Goal 的要求

`goal.md` 不是一句口号。根据项目需要写清：

- 长期目标和为什么值得持续推进；
- 当前背景与已知进度；
- 可用环境、数据、服务、机器和其他资源；
- 禁止触碰的边界、成本底线、安全限制和业务约束；
- 在长期目标之外必须兼顾的具体要求；
- 什么证据能够说明进展真实、什么情况需要人类判断。

Explorer 后续产生的每一条具体工作统一称为 Task。

## 项目标识

默认项目 ID 由目录名和绝对路径哈希组成，避免同名目录冲突。全局 Harness 通过 `project.yaml` 中的绝对路径映射到实际项目，不创建镜像目录或软链接。
